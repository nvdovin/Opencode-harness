# Тестовая стратегия harness

Эти правила действуют для всех проектов конвейера. Конкретные команды
берутся из `staff/test-strategy.json`, а не зашиваются в агентов.

## Профили

| Профиль | Что запускается | Когда | Бюджет |
|---|---|---|---|
| `fast` | unit/static/design-tokens, без БД | после каждого изменения | < 60 с |
| `affected` | затронутые приложения + route/smoke + a11y/design | reviewer на спринт | < 5 мин |
| `full` | весь сьют проекта | граница волны, QA, релиз | < 10 мин |
| `e2e` | браузерные/сквозные сценарии | волна/QA/релиз | < 5 мин |

`full` запускается не чаще одного раза на волну и один раз на релиз/QA.
Внутри параллельных ревьюеров полный сьют не запускается: если несколько
ревьюеров работают одновременно, они используют `affected`, а `full`
выполняет оркестратор на границе волны.

## Правила запуска

- Implementer: только targeted/`fast`; полный сьют — запрещён.
- Reviewer: `affected`; `full` — только если затронуты shared-файлы
  (модели, миграции, settings, urls, базовые шаблоны, общие JS/CSS)
  или если это явно требует оркестратор.
- Orchestrator: `full` один раз на границе волны; результат кэшируется
  по хэшу git-дерева.
- QA/релиз: `full` + `e2e` один раз.
- Перед запуском проверь, что зелёный `full` для текущего дерева уже есть:
  `run_profile.py --profile full --reuse-green-full` переиспользует его.

## Быстрый профиль

Для Django в тестовых настройках:

- `PASSWORD_HASHERS = ['django.contrib.auth.hashers.MD5PasswordHasher']`
  (тесты, которые проверяют именно хэширование, переопределяют настройку);
  шаблон быстрых настроек — `templates/django-test-fast.py`;
- `--keepdb`;
- `--parallel 2` на 2 vCPU/2 GB; не `4`;
- `setUpTestData` вместо `setUp` для неизменяемых данных;
- `force_login`/`force_authenticate` вместо реального логина;
- `create_user(..., password=None)` / unusable password там, где пароль
  не проверяется.

Для других стеков — аналогичный быстрый профиль: без реального хэширования,
без сети, без sleep, с переиспользованием тестовой БД/контейнера, если это
поддерживает фреймворк.

## Качество тестов

- Новый тест привязан к требованию/критерию; тесты «на всякий случай» и
  дублирующие матрицы запрещены.
- Бюджет: 10–20 новых тестов на спринт; превышение — обоснование в changelist.
- Один тест = одно поведение. Повторяющиеся случаи — `subTest`/параметризация.
- Не тестируем реализацию (приватные методы, классы, grep по исходникам),
  если это не дизайн/a11y-контракт.
- Никаких `sleep` и реальной сети в unit-тестах; slow/e2e — отдельные теги.
- Медленные тесты (> 2 с) чинятся или тегируются; топ-10 медленных
  проверяется на каждом QA.
- Reviewer отклоняет `test_bloat` и `slow_test`, а не только отсутствие тестов.

## Кэш прогонов

`run_profile.py` пишет `staff/test-runs.json`:

- профиль, команда, exit code, длительность, timestamp;
- `git_head` и `tree_hash` (HEAD + diff + untracked);
- список targets.

Зелёный `full` для того же `tree_hash` можно переиспользовать. После
изменения кода хэш меняется — кэш инвалидируется.

## Артефакт `staff/test-strategy.json`

```json
{
  "profiles": {
    "fast":     {"command": "...", "timeout": 120,  "budget_seconds": 60},
    "affected": {"command": "... {targets}", "timeout": 600, "budget_seconds": 300},
    "full":     {"command": "...", "timeout": 1800, "budget_seconds": 600},
    "e2e":      {"command": "...", "timeout": 900, "budget_seconds": 300}
  },
  "test_map": {
    "accounts/**": ["accounts", "tests.test_route_matrix"],
    "templates/**": ["tests.test_design_regression", "tests.test_a11y"]
  },
  "full_if_changed": [
    "**/models.py", "**/migrations/**", "**/settings/**", "**/urls.py",
    "templates/base.html"
  ]
}
```

Если `test_map` не покрывает изменённый файл — безопасный fallback: `full`.
Если менялся файл из `full_if_changed` — сразу `full`, без affected.
