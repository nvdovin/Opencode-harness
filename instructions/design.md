# UI/UX-правила harness

Эти правила действуют для всех фронтенд-работ. Пайплайн не навязывает
конкретную палитру и не хранит hex-значения: он требует, чтобы цвета,
фон и типографика были **семантическими токенами проекта**.

## Главный принцип

- Нет `staff/design-brief.md` — нет новой фронтенд-работы. Для легаси-спринта без брифа допускается review по `instructions/design.md` + существующим токенам с предупреждением `legacy_no_design_brief`.
- Нет скриншотов 375/768/1440 — нет `DESIGN: PASS`.
- Нет проверки UX/UI — UI-спринт не закрывается.
- Нестилизованные компоненты запрещены.

## Цвета и фон

- В разметке и компонентах используются только семантические токены:
  `--color-bg`, `--color-surface`, `--color-text`, `--color-muted`,
  `--color-border`, `--color-accent`, `--color-accent-contrast`,
  `--color-danger`, `--color-success`, `--color-focus`.
- Значения токенов берутся из существующей дизайн-системы проекта,
  брендбука или отдельного решения пользователя. Агенты не выбирают
  «красивые» hex-значения самостоятельно и не зашивают их в промпты,
  шаблоны или скрипты.
- `hex` вне `:root`/токенов — 0; inline-стили с цветом — 0.
- Контраст текста и интерактивных элементов — не ниже WCAG AA.
- Акцент используется для действий и фокуса, а не для декора.
- Количество смысловых цветов ограничено дизайн-брифом; новый оттенок
  добавляется только как токен с ролью.
- Тёмная/светлая тема, если есть, использует те же роли токенов.

## Композиция

- Контент в центрированном контейнере; левый и правый отступы равны.
- Сетка карточек: равные ширины и высоты в ряду, одинаковые gap.
- Один primary CTA на экран/секцию; остальные — secondary/tertiary.
- Длинный текст — 45–75ch; не растягивать на всю ширину экрана.
- Section padding — из шкалы отступов проекта; без «случайных» значений.
- Не допускаются: горизонтальный скролл, налезание интерактивных элементов,
  обрезанный контент, карточки-«полотно» на десктопе, вложенные карточки,
  огромные пустоты без смысла.
- Симметрия важнее декора: выравнивание по сетке, одинаковые отступы,
  одинаковые радиусы и высоты.

## Компоненты

Каждый интерактивный компонент имеет вариант из дизайн-системы:

- Button: primary / secondary / ghost / danger; состояния default, hover,
  focus-visible, active, disabled, loading.
- Input, textarea, select, file input: label, hint, error, disabled,
  focus-visible; нативный внешний вид не допускается.
- Card, table, tabs, modal, toast, empty state, pagination.
- Иконки — с `aria-hidden` или доступным именем; декоративные — скрыты.

Запрещено:

- видимый `select` с `appearance: auto`;
- нативный `input[type=file]` без стилизованной обёртки;
- кнопка без класса/варианта дизайн-системы;
- `outline: none` без замены на focus-visible;
- `!important` вне reset/утилит.

## UX

- Один понятный следующий шаг; никаких тупиков.
- Обратная связь на действие: loading, success, error, empty.
- Ошибки — рядом с полем/блоком, на русском, без `alert()`.
- Деструктивные действия — с подтверждением; опасные — с явной пометкой.
- Клавиатура: Tab-порядок, Escape для модалок/меню, возврат фокуса.
- Touch target ≥ 44 px; мобильная версия — не «уменьшенная копия» десктопа.
- Тексты интерфейса — на языке проекта (по умолчанию русский).

## Адаптив

Проверяются минимум 375, 768 и 1440 px:

- нет горизонтального скролла;
- навигация и таблицы не ломаются;
- карточки перестраиваются в 1–2 колонки;
- кнопки не выходят за вьюпорт;
- длинные слова/ссылки не рвут layout.

## Доступность

- WCAG AA по контрасту.
- У полей — label/aria-label; у изображений — alt.
- Модалки/меню — role, aria-*, focus trap, Escape.
- `prefers-reduced-motion` для анимаций.
- Ошибки форм связаны с полями (`aria-describedby`).

## Дизайн-ревью

Обязательный порядок:

1. `staff/design-brief.md` утверждён.
2. В spec есть «Дизайн-контракт»: страницы, компоненты, состояния, viewport.
3. После реализации `ui-design-reviewer` снимает скриншоты и считает
   DOM-метрики (overflow, overlap, симметрия, сетка, плотность, контролы).
4. Агент читает скриншоты и проверяет иерархию, шум, баланс, пустоты.
5. Вердикт `DESIGN: PASS` или `FAIL`; blockers и majors — в отчёт.
6. Без PASS UI-спринт не закрывается.

Если UI не менялся — фиксируется `N/A — no UI changes`.

## Анти-паттерны

- 4 CTA в hero, два из них primary.
- Карточки на всю ширину с пустотой справа.
- Нативные select/file input/checkbox.
- Разные высоты кнопок и карточек в одном ряду.
- Случайные отступы и радиусы.
- Градиенты и тени «для красоты» без роли.
- Текст на всю ширину экрана.
- Модалка без focus trap и Escape.
- «Красиво на десктопе, сломано на 375».
